# 상하차의 신 — 멀티플레이 「난투」 설계 (v0.1)

## 0. 한 줄

**4인이 각자 시계로 석 달을 굴린다. 끝까지 살아남고, 살아남은 사람끼리는 잔액으로 겨룬다.**
개인 런이 "차분히 쌓는 판"이라면 멀티는 "펑펑 터지는 판"이다. 규칙은 개인 런에서 **빼고**(새 계약·배차 제한·어음·명절), 연출과 상호작용을 **더한다**(트레잇·보수공사·퍽 3택1).

이 문서의 모든 규칙은 **멀티 전용**이다. 개인 런·캠페인은 건드리지 않는다.

## 1. 경기 규칙

| 항목 | 값 |
|---|---|
| 인원 | 2~4인 (4인 목표, 매칭 대기 후 미달이면 봇으로 채움 — §9) |
| 길이 | 석 달 = 6사이클(반월) = 약 72영업일. 명절·연휴 없음(달력은 시각만) |
| 시간 | **공유하지 않는다.** 각자 자기 날짜를 진행한다 (§2) |
| 종료 | 평판 0 → **폐업**(기존 규칙 그대로). 잔액이 마이너스면 호출을 못 해 물량이 쌓이고 결국 평판으로 죽는다 — 죽는 이유는 개인 런과 같이 하나다 |
| 승부 | ① 생존자 > 폐업자 ② 생존자끼리 **최종 잔액** ③ 동률이면 평판 ④ 폐업자끼리는 늦게 죽은 순 |
| 입고 시드 | **매치 공유** — 넷이 같은 입고 대본을 받는다. 운은 트레잇 발동과 보수공사 목적지에만 있다 |
| 물량 | 일차에 비례해 오른다: `arrivals × (1 + 0.025 × day)`, 마지막 보름은 ×1.5 「마감 폭주」 |

## 2. 시간 — 눌러야 간다, 마켓도 하루다

타이머 없음. 개인 런처럼 호출·대기를 눌러야 다음 날이다. 넷의 시계는 각자 돈다.

- **마켓에 들어가는 것이 하루를 쓴다.** 마켓 = 「장 보러 간 날」: 입고는 쌓이고 배송은 없다. 그래서 자주 못 들어가고, 들어가면 한 번에 사고 나와야 한다(§6). "마켓에서도 시간이 간다"는 이 한 줄로 구현된다.
- 퍽 3택1·창고 팝업·상대 포트레잇 탭은 시간을 쓰지 않는다.
- 주말 카드 없음. 일요일은 그냥 지나간다(입고만 쌓임).
- 상대에게서 온 공격은 **받는 사람이 다음 날로 넘길 때** 적용된다(큐). 빠른 사람은 일찍 쏘고, 느린 사람은 초반 날짜에 그걸 다 맞는다 — 서두를 이유가 여기서 난다.
- **먼저 끝낸 사람** = 「마감」. 잔액 확정, 이후 날아오는 공격·보수공사은 무효(닫은 창고엔 못 넣는다), 남은 사람들을 관전. 마감한 뒤 큐에 남아 있던 내 공격은 그대로 나간다.
- 마지막 30일부터 HUD에 **D-카운트**.

## 3. 택배 트레잇 — 출고하면 터진다

멀티에서는 입고 택배의 일부(초반 15% → 후반 35%)에 트레잇이 붙는다. **기한 안에 출고하면 발동**, 반송·폐기되면 불발. 아이콘 하나로 읽혀야 한다(개인 런의 품목 아이콘 옆 작은 뱃지).

### 공격 (**나 빼고 전원에게** — 살아있고 마감 안 한 상대 모두)

| 아이콘 | 이름 | 상대에게 |
|---|---|---|
| 🏗 | 보수공사 | §4 |
| 🌧 | 소나기 | 다음 날 야외 적재 전부 「젖음」(기한 −1) |
| 📞 | 클레임 | 평판 −1 |
| 🐭 | 쥐 | 신선 품목 1개 즉시 폐기 |
| ⏱ | 독촉 | 창고 안 모든 택배 기한 −1 |
| 🚧 | 도로 통제 | 다음 날 호출 불가 |
| 💸 | 반품 | 반송 1건 강제(평판 −1 상당) |
| 🔒 | 창고 봉인 | 창고 상한 −3칸, 3일 |

### 보너스 (나에게)

| 아이콘 | 이름 | 효과 |
|---|---|---|
| 💰 | 웃돈 | 이 택배 보수 ×2 |
| ⭐ | 입소문 | 평판 +1 |
| 🛡 | 방패 | 다음 공격 1회 무효 (최대 2겹) |
| 🧊 | 얼음 | 신선 부패 정지 3일 |
| 📦 | 압축 | 창고 +3칸, 3일 |
| 🚚 | 덤 트럭 | 다음 호출 트럭 +1 무료 |
| 🔄 | 되돌리기 | 들고 있는 보수공사 1개를 보낸 사람에게 반송 |
| 🎯 | 한 방 | 다음 공격 트레잇을 **1위 한 명에게만** 보내되 효과 ×3 |

원칙: 전원에게 가는 대신 **한 방은 반나절 손해**를 넘지 않는다(개인 런 사고 하나의 절반). 죽이는 건 공격이 아니라 물량이어야 한다. 공격 트레잇은 등장 비율을 보너스보다 낮게(공격 40 : 보너스 60) 잡아 판 전체가 난타가 되지 않게 하고, 방패·되돌리기·한 방이 있으므로 "맞기만 하는" 판은 안 나온다.

## 4. 보수공사

개인 런의 이삿짐 보관 계약(공간만 쓰는 계약)을 멀티에서는 **보수공사**으로 뒤집는다.

- 트레잇과 달리 **랜덤 상대 한 명**에게만 간다(전원에게 가면 창고가 동시에 터진다).
- **강제 수락.** 마켓 계약이 아니라 입고로 들어온다. 거절 불가, 출고 불가.
- 크기 3칸, 보관료 소액(하루 +2c)이 들어온다 — 그래서 완전히 손해는 아니지만 자리를 먹는다.
- **카운트다운 6일.** 0이 되면 「이사 완료」 — 내 창고에서 사라지고 **랜덤 상대 창고로 날아간다.** 옮겨갈 때마다 **+1칸, 카운트 −1일**(3칸/6일 → 4칸/5일 → 5칸/4일 …). 돌수록 무거워진다.
- 소멸 조건: ① 6칸/1일까지 커진 보수공사은 다음 이사 때 **터진다** — 받은 사람 창고 초과분 도난 판정 1회, 그 뒤 소멸 ② 들고 있던 사람이 폐업하면 같이 소멸 ③ 마감한 사람에겐 못 간다.
- 매치당 동시 보수공사 **최대 4개**(인원 수). 발생원은 🏗 트레잇 출고와 매 사이클 정산 1개 자동 투하.
- 연출: 트럭이 내 창고에서 상대 포트레잇으로 날아가 **쿵** 하고 박힌다. 받는 쪽 화면은 흔들리고 3D 마당에 이삿짐 더미가 실제로 놓인다.

## 5. 평판 → 퍽 3택1

개인 런의 평판 등급(무명·동네 소문·구내 유명·시내 최고)은 멀티에 없다. 평판 게이지는 그대로(0이면 폐업), **등급 문턱을 넘을 때마다** 퍽 카드 3장이 뜨고 1장을 고른다.

- 문턱: 상한 도달 → 상한 +5·등급 +1(개인 런과 같은 사다리). 석 달이면 4~6번.
- 카드는 3계열에서 하나씩 뽑는다. **장착 상한 없음**, 같은 퍽 중복 가능(중첩 수치 표기).
- 팝업은 시간을 쓰지 않는다. 느긋하게 고른다.
- 런 시작 퍽(개인 런의 회사·퍽 선택)은 **없다.** 멀티는 전원 같은 창고·같은 계약으로 시작한다.

| 계열 | 예시 |
|---|---|
| 🛡 방어 | 상시 방패 1겹 · 보수공사 카운트 +2일 · 받는 공격 50% 확률 불발 · 소나기 면역(지붕) |
| ⚔ 공격 | 공격 트레잇 등장 +10%p · 보수공사 옮길 때 +2칸 · 내 공격 효과 ×1.5 · 내 보수공사 이사 시 상대 평판 −1 |
| 💰 경제 | 연속 만차 보너스 ×1.5 · 트럭 1대 무료/일 · 보관료 ×3 · 마감 폭주 보수 +20% · 업그레이드 −20% |

값은 개인 런 퍽 상한(월 40~80c)을 **의도적으로 넘긴다.** 석 달짜리 난투에서 퍽은 양념이 아니라 빌드다.

## 6. 마켓 — 한 화면, 새 계약 없음

들어가면 하루가 가므로(§2) **한 번에 사고 나오는** 화면이어야 한다.

- 언제든 들어갈 수 있다(정산 뒤가 아니라 HUD 버튼, 「장 보기 · 하루」 라벨). 정산은 자동, 팝업 없이 로그 한 줄.
- 내용은 **보유 계약 카드 3장 + 창고 카드 1장**뿐. 매물 없음, 새로고침 없음.
- 계약 카드: 이름·트럭 아이콘 · [▲ 업그레이드 비용] 한 버튼 · 강화 칸 아이콘 줄(냉장·대형·파손 등, 각각 한 버튼). **배차 항목 없음**(배차 제한이 없으므로 리필·한도 업그레이드 삭제).
- 창고 카드: [+칸 비용] · [냉장 +칸] · [마당 +칸].
- 결제는 **즉시 차감**(어음 없음 — 잔액이 곧 점수이므로 눈에 보이는 숫자가 실제 숫자여야 한다). 돈이 모자라면 버튼 회색, 이유 한 줄.
- 시작 계약은 넷 모두 같은 3개(일반·대량·냉장). 차이는 무엇을 먼저 키우느냐에서 난다.

배차 무제한 = 호출은 **배차비만** 든다. 트럭 수 상한도 없다. 대신 배차비가 일차에 따라 조금씩 오른다(유가).

## 7. HUD — 상대가 보인다

상단 한 줄에 **포트레잇 4개**(맨 왼쪽 나). 각 포트레잇 아래:

- 창고 적재 막대(초록→노랑→빨강, 초과는 깜빡임)
- 평판 점 5개
- 잔액 (작게, 순위 색: 1위 금테)
- 진행 일차 (`D+41`) — 시계가 다르니 이게 있어야 "저 사람은 벌써 끝나간다"가 읽힌다

표정은 상태를 따라간다: 기본 / 창고 80%↑ 진땀 / 공격 맞음 놀람 / 1위 웃음 / **폐업 = 그레이아웃 + 망연자실**(표정 프레임 하나 추가). 마감한 사람은 세피아 + 「마감」 도장.
포트레잇을 탭하면 그 사람 창고 요약(계약 3줄·들고 있는 보수공사·퍽 아이콘) — 관전 정보이지 조작 아님.

## 8. 연출 — 여기가 본체

개인 런 것을 다 쓰고 더 얹는다. 전부 화면 중앙 팝 + SFX, 겹치면 큐.

| 트리거 | 연출 |
|---|---|
| 연속 만차 (80%↑ 연속) | 기존 그대로 + 5연속부터 배수 라벨 커짐(×1.2 → ×1.5 → ×2) |
| 점보 / 일괄 출고 | 기존 그대로 + 트럭 대수만큼 포트레잇 밑 잔액이 굴러 올라감 |
| 공격 발사 | 내 창고 → 상대 포트레잇으로 아이콘 궤적, 명중 시 상대 포트레잇 흔들림 + 표정 |
| 피격 | 화면 가장자리 빨간 비네트 0.3초 + 무엇을 당했는지 한 줄 |
| 방패 발동 | 포트레잇 앞에 방패 깨지는 프레임 |
| 보수공사 도착·이사 | §4 |
| 퍽 획득 | 카드 3장 슬라이드, 고르면 나머지 재가 됨 |
| 평판 등급업 | 팡파레 + 게이지 늘어남 |
| 순위 변동 | 「2위로 올라섰다」 토스트, 1위 탈환은 금색 |
| 폐업 (누구든) | 전원 화면에 「○○ 폐업」 배너 + 포트레잇 그레이아웃 |
| 마감 | 「○○ 마감 · 잔액 12,400c」 배너 |
| D-30 / D-7 / D-1 | 카운트 배너, 마지막 날은 BGM 템포 업 |

효과 밀도 목표: **하루에 최소 하나는 뭔가 터진다.**

## 9. 등급 · ELO · 매칭

- 등급(택배 테마): 견습 기사 → 정규 기사 → 조장 → 팀장 → 지점장 → 본부장 → **상하차의 신**. ELO 구간 200씩, 시작 1200.
- 4인 ELO: 순위표에서 **모든 쌍**을 1:1 결과로 계산해 합산(4인 = 3경기 분). K = 32, 30판 후 16.
- 매칭: 같은 등급 ±1 → 30초 후 ±2 → 60초 후 봇 채움(봇은 ELO 변동 반영 안 함, 등급 상위에서는 봇 없음).
- 2인 매치 허용(친구 초대 코드). 초대 매치는 ELO 미반영.
- 리더보드는 이미 결정한 **자체 서버 하나**(웹·Android·Steam 공용)에 얹는다.

## 10. 서버 (개요만)

- 각 클라이언트가 자기 판을 시뮬레이션(개인 런 엔진 그대로, 멀티 규칙 셋만 `_buildRules`에 추가). 서버는 **이벤트 중계 + 상태 스냅샷**(WebSocket): 공격·보수공사·잔액·평판·일차·표정 상태.
- 보수공사 목적지 랜덤은 **서버가 정한다**(클라 조작 방지).
- 매치 종료 시 서버가 각 클라의 입력 로그로 **재실행 검증**(같은 시드이므로 결정적). 안 맞으면 그 판은 무효·ELO 미반영.
- 끊긴 사람은 30초 자동 대기 처리, 3분이면 폐업 판정.

## 12. 결정된 것 · 열린 것

결정(2026-09-26): 시간은 **눌러야 진행·타이머 없음**, 공격 트레잇은 **나 빼고 전원**, 입고 시드는 **매치 공유**.

남은 질문:

1. 마켓이 하루를 쓰는 게 맞나 — 다른 해석은 "마켓은 시간을 안 쓰지만 사이클마다 1회". 하루 소모가 더 직관적이라 문서안으로.
2. 먼저 마감한 사람이 관전만 하는 게 심심하지 않은지 — 관전 중 응원 이모지 정도.
3. 보수공사 소멸 조건(6칸/1일에 터짐)이 너무 늦지 않은지 — 4인이면 한 바퀴 반이다.
4. 멀티 전용 시작 창고·계약 3종의 실제 값 — 개인 런 봄 시작값에서 창고 +4칸으로 시작하는 게 후보.
5. 전원 공격이라 공격 트레잇 비율(40%)과 한 방 세기(반나절)가 맞는지는 봇 3명 로컬 판에서 먼저 본다.

## 부록 C. 3단계 구현 — 서버 · 매칭 · 검증 · ELO · 등급 (2026-09-26)

### 서버는 어디에

리더보드(`www/api/scores.js`)와 같은 자리 — **Vercel 서버리스 함수 + Upstash Redis(REST)**. `www/api/match.js` 하나, `POST { op }` 로 `queue · leave · status · push · poll · finish · elo`.
10장은 WebSocket 을 말했지만 서버리스엔 상주 연결이 없다. 이 게임은 눌러야 진행·타이머 없음이라 실시간이 필요 없어 **폴링**으로 바꿨다: 큐는 2초, 판은 하루를 넘길 때 `push`(내 이벤트 + 스냅샷) 후 `poll`, 그 사이 3초마다 `poll`. 발사 연출이 한 폴링(≤3초) 늦게 뜨는 것이 대가다.
같은 저장소 환경변수(`KV_REST_API_URL/TOKEN`)를 쓰므로 **Vercel 에 따로 붙일 것은 없다**. 로컬·테스트는 `MATCH_MEM=1`(인메모리 스토어).

### 서버가 하는 일 넷

1. **큐·매칭** — 해시 `mq`(pid → 이름·얼굴·ELO·들어온 시각). `queue` 를 받을 때마다 짝을 맞춰 본다: 가장 오래 기다린 사람 기준 같은 등급 ±1(ELO ±200) → 30초 뒤 ±2 → 60초 뒤 봇으로 채움(팀장 이상은 봇 없이 계속 기다린다). 매치 = `{ id, seed(서버가 정한다), players[{pid, name, face, elo, bot, host}], rated }`. 첫 사람이 **호스트** — 봇은 호스트 클라이언트가 돌리고 봇 몫 스냅샷·이벤트·결과도 호스트가 올린다.
2. **중계** — 클라이언트 `outbox`(공격 발사·보수공사 이사·사이클)를 서버가 **목적지를 붙여** 이벤트 리스트 `me:mid` 에 쌓는다. 공격은 나 빼고 살아 있고 마감 안 한 전원, 🎯 한 방은 그중 잔액 1위, **보수공사 목적지는 서버 난수**(클라 조작 방지), 동시 보수공사 상한 4(스냅샷 합계), 사이클 투하는 사이클당 한 번. 남의 이름(`from`)으로는 못 보낸다 — 호스트는 봇 이름으로만 더 보낼 수 있다. `poll` 은 커서 뒤 이벤트 중 나(와 내 봇)에게 온 것 + 전체 스냅샷 + 결과.
3. **폐업 판정** — 스냅샷이 3분 넘게 안 오면 `gone` 으로 친다(공격 대상에서 빠지고 화면엔 폐업). 10장의 "30초 자동 대기"는 서버가 판을 돌리지 않아 못 한다 — 안 한다.
4. **종료·검증·ELO** — `finish` 에 결과 + **입력 로그**(`actLog`)가 온다. 서버가 `MULTI.replay` 로 같은 시드에서 다시 돌려 잔액·평판·일차·승패가 같은지 본다(`MULTI.verify`). 넷이 다 끝나면 순위(생존 > 잔액 > 평판 > 늦게 죽은 순) → **사람끼리 모든 쌍을 1:1 ELO**(K 32, 30판부터 16). 봇과의 쌍은 안 센다. 한 사람이라도 검증에 실패하면 그 판은 **무효**(`settled.void`) — 아무도 안 움직인다.

### 입력 로그 (`game.actLog`)

멀티 판의 모든 행동과 **수신**을 순서대로: `wait{ids} · call{i,ids,n} · self{ids} · shop · buy{i,s,m} · close · perk{id} · atk{a} · bomb{b}`. 받은 공격·보수공사까지 로그에 있어야 같은 판이 재현된다(적용 시점은 로그 순서가 정한다). 석 달치 ~10KB.

### 규칙 손질 — "막히는 게 아니라 스피드감"

유저 피드백 셋을 그대로 규칙에 넣었다.

1. **배차는 횟수로** — 배차비를 못 내서 막히는 순간이 판을 깬다(`"배차비 못내는거 너무 깬다. 그냥 횟수로 하자"`). `unlimitedCalls:false · noCallFee:true · fuelRate:0` — 배차 칩(횟수)은 캠페인처럼 돌아오고 돈은 안 든다. 사이클 끝 장에 **배차 충전 카드**(`refill`)가 다시 선다.
2. **멀티엔 확인 대화 없음** — 장에서 업그레이드 계약을 누르면 대화 없이 바로 갈아탄다(`buyContractInto(..., true)`).
3. **승부는 평판** (`repDecides:true`) — 순위 = 생존 > **최종 평판** > 잔액. 돈은 보조 지표(줄·표에 작게).
4. **먼저 마감한 사람 빼고 평판 페널티** (`latePenaltyDiv:3`) — 첫 마감 순간에 나머지가 남긴 날 ÷ 3(올림)만큼 최종 평판에서 뺀다. 첫 마감자는 면제. 유저의 최종 결정: `"1등한 사람 제외하곤 평판 페널티"` (일찍 끝낸 만큼 올려주는 안은 버렸다 — 페널티가 같은 얘기를 더 급하게 한다).
   - 클라이언트: `MULTI.noteFinish(match, pid)` 가 `match.firstFinish = { pid, days:{pid: 그때 일차} }` 를 기록, `penaltyOf(match, p)` 가 표시·순위에 쓴다. 저장에도 남는다.
   - 서버: `finish` 가 첫 승리 마감에 `m.firstFinish` 를 기록(스냅샷 일차로), `rankRows` 가 `repFinal = rep − penalty` 로 정렬 → `settled.rows[].repFinal/penalty`, `settled.first`.
   - 결과 화면 첫 줄: 「○○가 먼저 마감 — 나머지는 남은 날만큼 평판 −(3일에 1)」(`multi.firstNote`).

### 덧 (2026-09-27) — 평판만 · 굴러가는 숫자 · 이어하기 삭제

유저: **"돈은 중요하지 않으니 이제 평판만 보이면 될 거 같아. 평판은 한번에 올라가지 말고 이펙트랑 함께 생동감 있게 실제 숫자가 변하는 걸 애니메이팅해서. 그리고 난투 이어하기는 굳이 필요 없는 거 같아."**

- **평판만** — 상대 카드는 `★평판`(−페널티) 한 줄, 잔액 삭제. 결과표도 평판만(총 수익·지출 줄 삭제), 프로필 `multi.best` 는 최고 평판. HUD 자금 칸은 난투에서 접고(`#hud-cash-box` hidden) 장·캠페인에 필요한 잔액만 `#hud-due` 자리에 작게.
- **굴러가는 숫자** — `animNum(el, from, to, fmt)`(rAF, ease-out, 350~900ms)·`pulse(el, 'rep-up'|'rep-down')`. HUD `#stress-num` 은 마지막으로 보여 준 값(`hudRep`)에서 이어 굴러가고 게이지는 CSS transition, 난투에선 `★+N` 플로트까지. 상대 카드는 `stripRep` 에 카드별 마지막 값을 들고 있어 `innerHTML` 로 다시 그려도 직전 값에서 이어진다. 오르면 금빛 확대, 내리면 붉게 흔들림.
- **이어하기 삭제** — 난투는 저장하지 않는다(`saveGame` 이 멀티면 키를 지운다). 타이틀 「난투 이어하기」·새 판 확인 대화 삭제. 온라인 판도 재접속 이어하기 없음(나가면 3분 뒤 폐업 처리 그대로).
- **평판 0 은 폐업이 아니다** (`noRepEnd:true`) — 평판이 점수인데 바닥에서 탈락시키면 "막히는" 판이 된다. 그냥 꼴찌. (테스트가 이걸로 흔들렸다: 8일차에 평판 0 폐업 → 결과 모달 없음.)
- 응원 말풍선은 `bubbles[pid]` 로 남은 시간을 들고 있어 카드 재렌더에도 살아 있다.

- **평판은 택배마다 +1** (기한 넘긴 건 0). 빨리 보내는 것만으로 쌓이지 않고, 처리한 양만큼 서서히 오른다.
- **⚡ 긴급**(일반 12%, 그날 기한): 트럭에 **그 택배 하나만** 싣거나 **직배**로 보내면 +4 추가. 다른 택배와 섞으면 그 호출의 평판이 **절반**. 호출 화면에 「⚡ 긴급 단독」/「⚡ 섞임 — 평판 ½」 칩.
- **특약은 호출마다 종류당 한 번** — 같은 특약 택배를 셋 실어도 한 번. 대신 **한 특수 종류로만 트럭을 가득 채우면** 그 특약이 **×2**로 터진다(「만차 — 특약 ×2」 칩 · 버스트). 따로따로 자주 보낼지, 모아서 한 방에 보낼지 고민.
- 특수 화물은 전부 제 종류의 특약을 가진다(수는 적다).
- **첫 상점이 빨리**: 시작 평판 +3이면 첫 상점(전문화 고르기) — 보통 2~4일차. 그 뒤 단계 폭은 3 → 6 → 9 … 최대 20.
- 시뮬(봇 10판): 첫 상점 2~4일, 끝 등급 11~18, 최종 평판 평균 ~186.
