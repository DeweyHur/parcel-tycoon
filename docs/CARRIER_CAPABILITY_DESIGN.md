# 택배 타이쿤 — 업체 능력 체계 · 난이도 기획서 v0.2

`GAME_DESIGN.md`(런 내부 규칙 v0.2)와 `META_DESIGN.md`(메타 진행 v0.1) 위에 얹는 문서다. 고객·손실·보험·보관 계약은 `CUSTOMER_DESIGN.md`에 있다.

v0.2 변경: 🌐 국제 속성을 🛃 **통관**으로 교체(창고 관점의 "시간" 성질), ❆ **냉동** 추가, ⚠ 파손과 ❄ 신선은 "필수 능력"에서 "없으면 위험"으로 완화. 시나리오 택배(구 3장)는 고객 품목으로 흡수.

플레이테스트 동기: 파손 2짜리가 창고에 있는데 마켓을 6번 새로고침해도 프래자일 전문이 안 나왔다. 원인은 (a) 매칭이 정확 일치라 파손을 처리할 계약이 사실상 하나뿐이고, (b) 마켓이 창고 상태를 보지 않아 새로고침이 복권이 되기 때문이다. (b)는 v0.3.4에서 고쳤고(2장), 이 문서는 (a)를 구조적으로 고친다.

## 1. 속성과 능력

### 1.1 택배 속성 — 네 가지 성질

택배 속성은 창고에서 **어떤 일이 벌어지는지**로 정의한다. "어디로 가는지"는 창고가 알 바 아니다.

| 속성 | 아이콘 | 창고에서 벌어지는 일 | 성질 | 처리 업체 |
|---|---|---|---|---|
| 신선 | ❄ | 냉장 구역 밖이면 다음 턴 폐기 | **공간** | 아무 업체 (보너스는 냉장 전문만) |
| 파손 | ⚠ | ⚠ 능력 없는 업체로 보내면 파손 확률 | **위험** | 아무 업체 (⚠ 없으면 25%, 자체 배송 40% 파손) |
| 통관 | 🛃 | 입고 후 2턴 통관 대기 — 어떤 업체로도 처리 불가, 자리만 차지. 대기 뒤 기한 시작 | **시간** | 대기 후 아무 업체. 통관 대행 업체는 대기를 건너뜀 |
| 냉동 | ❆ | 냉동 구역 밖이면 즉시 폐기 | **계약** | ❆ 능력 업체만 |
| (크기) | 숫자 | 점유량 1·2·4·7 | | 크기 4+는 대형 업체 등 크기 범위로 |

속성은 이 넷으로 고정한다. 속성 2개 택배(❄🛃 수입 수산물, ⚠🛃 직구 전자기기 등)는 고객 품목으로만 나온다. 속성 3개는 없다.

통관 대기 중 "통관 지연 +1턴" 이벤트가 20% 확률로 붙는다(입고 시 표시). 통관 대기 택배는 목록에 🛃N 뱃지로 남은 대기 턴을 보여준다.

### 1.2 업체 능력

업체는 `caps`(능력 집합), `sizeMin/sizeMax`, 회당 처리량, 지연 턴으로 정의한다.

> 처리 가능 = 크기가 범위 안 && (❆이면 caps에 ❆ 필요) && (🛃이면 통관 대기가 끝났거나 caps에 🛃)
> ⚠·❄는 처리 가능 여부에 영향 없음. ⚠ 없는 업체는 파손 확률, 냉장 전문 아니면 신선 보너스 없음.

기존 업체를 옮기면 다음과 같다.

| 업체 | caps | 크기 | 회당 | 지연 | 비고 |
|---|---|---|---|---:|---|
| 자체 배송 | {} | 1~2 | 부피 2 | 0 | 상설, 보상 70%. 일반(속성 없음)만 — 파손 40% 규칙은 자체 배송이 ⚠를 받게 될 때 적용 |
| 용달 (구 타겟 멀티모달) | {} | 1~7 | 1 | 0 | 무엇이든 1개, 파손 25%, ❆ 불가 |
| 냉장 물류 | {❄} | 1~4 | 3 | 0 | 전문. 신선 보너스 |
| 냉동 물류 | {❆❄} | 1~4 | 2 | 0 | 신규. 냉동 보너스, 신선도 가능 |
| 프래자일 전문 | {⚠} | 1~4 | 3 | 0 | 전문. 파손 보너스 |
| 통관 대행 (구 국제 특송) | {🛃} | 1~7 | 2 | 0 | 통관 대기 중인 택배를 즉시 통관·발송. 통관 보너스 |
| 대량 분류 | {} | 1~2 | 4 | 0 | 파손 25% |
| 대형 화물 | {⚠} | 4~7 | 2 | 0 | 크기 기준. 대형 보너스 |
| 긴급 특송 | {⚠🛃} | 1~7 | 1 | 0 | 즉시 행동 |

### 1.3 원형(운송 수단) 업체

운송 수단은 택배가 요구하는 조건이 아니라 **업체의 성격**이다. 카드 뱃지 하나로만 표현하고 매칭에는 관여하지 않는다.

| 업체 | 뱃지 | caps | 크기 | 회당 | 최대 호출 | 지연 | 가격 | 역할 |
|---|---|---|---|---:|---:|---:|---:|---|
| 항공 특송 | ✈ | {🛃⚠} | 1~2 | 2 | 3 | 0 | 260 | 소형 통관·파손 겸용. 비싸고 작지만 빠르다 |
| 철도 수송 | 🚆 | {⚠} | 1~7 | 5 | 2 | 1 | 190 | 파손을 싸게 대량으로. 호출 다음 턴에 배송 |
| 해상 운송 | 🚢 | {🛃❄} | 2~7 | 4 | 2 | 2 | 230 | 통관·냉장 컨테이너. 느리지만 많이 |
| (지상) | 🚚 | 기존 전문 업체 | | | | | | 뱃지만 추가 |

지연 N: 호출 턴에 창고에서 빠지고 잔여 호출도 차감되지만, 보상은 N턴 뒤에 들어온다. 보상은 호출 시점 기한 기준.

### 1.4 전문 업체의 존재 이유

- 특수 운송 보너스(신선 +10, 파손 +15, 통관 +20, 대형 +25, 냉동 +20)는 caps가 정확히 그 속성 하나인 전문 업체로 처리했을 때만.
- 신뢰 3단계 전용 능력은 전문 업체 고유. 원형 업체의 3단계는 "지연 -1"로 통일.
- ⚠ 능력은 파손 확률을 0으로 만드는 것이 가치. 전문이 아니어도 ⚠가 있으면 안전하지만 보너스는 없다.

### 1.5 속성 특약 (강화 아이템)

계약 하나에 속성 하나를 추가한다. 계약당 1개, 계약 교체 시 소멸, 특약 처리는 보너스 없음.

| 특약 | 효과 | 기본 가격 |
|---|---|---:|
| 완충 포장 특약 | caps에 ⚠ (파손 확률 0) | 150 |
| 보냉 특약 | caps에 ❄ (신선 보너스 절반), 회당 -1 | 170 |
| 통관 대행 특약 | caps에 🛃, 계약 최대 호출 -1 | 190 |
| 냉동 컨테이너 특약 | caps에 ❆, 회당 -1, 크기 최대 4 이하 계약만 | 220 |

## 2. 마켓 보장 규칙 (v0.3.4 구현됨)

창고에 있거나 다음 2턴 입고 예정인 택배 중 현재 계약(용달·긴급 제외, 잔여 호출 있는 것)으로 처리 불가능한 것이 있으면 슬롯 A에 처리 가능 업체를 배치하고 힌트를 붙인다. `rules.guaranteeBlocked`로 끌 수 있다.

v0.2 매칭에서는 "처리 불가능"이 ❆와 크기뿐이므로 이 규칙의 발동은 줄어든다. 대신 **위험 경고**를 추가한다: 창고에 ⚠ 택배가 있는데 ⚠ 업체가 없으면 슬롯 A 후보에 ⚠ 업체·완충 특약을 가중치 ×3.

## 3. 시나리오 택배 → 고객 품목

v0.1의 시나리오 택배(수입 해산물·정밀 기계·귀중품·급행·반품·냉장 대형)는 `CUSTOMER_DESIGN.md` 2장의 고객 품목으로 흡수했다. 시나리오는 고객 명단을 조정하는 방식으로 정의한다.

## 4. 난이도

시나리오 → 난이도 → 회사 → 퍽 순서로 고른다. 난이도는 시나리오 규칙에 곱해지는 얇은 층이다.

| 항목 | 수습 | 정규 | 베테랑 |
|---|---:|---:|---:|
| 입고량 | ×0.9 | ×1.0 | ×1.15 |
| 월말 운영비 | -20 | 0 | +30 |
| 마켓 가격 | ×0.9 | ×1.0 | ×1.1 |
| 막힌 속성 보장(2장) | 켬 | 켬 | **끔** |
| 도난·파손 확률 | ×0.5 | ×1.0 | ×1.5 |
| 손해배상 배율 | ×0.5 | ×1.0 | ×1.5 |
| 속성 2개 택배 | 없음 | 고객 정의대로 | 고객 정의 + 3%p |
| 입고 예정 표시 | 3턴 | 2턴 | 2턴 |
| 스트레스 게임오버 | 24 | 20 | 18 |
| 점수 배율 | ×0.7 | ×1.0 | ×1.4 |

- 회사·시나리오·퍽 해금 도전과제는 정규 이상에서만 인정. 데일리는 정규 고정. 베테랑은 첫 클리어 후 해금.
- 봇 시뮬 목표: 정규는 `META_DESIGN.md` 9장 승률표, 수습 +20%p, 베테랑 -20%p 안팎.

## 5. UI · 아이콘 규칙

- 속성 아이콘은 ❄ ⚠ 🛃 ❆ 넷과 크기 숫자뿐. 택배 칩, 업체 카드, 특약, 도감 모두 같은 기호.
- 운송 수단 뱃지(✈🚆🚢🚚)는 업체 카드 좌상단 한 자리. 택배에는 절대 붙이지 않는다.
- 지연은 ⏱1/⏱2, 특약 속성은 점선 테두리 칩, 통관 대기는 🛃2 (남은 턴).
- 호출 모달에 **위험 미리보기**: "⚠ 파손 25% (2개 중 예상 0.5개) · 배상 최대 110c".
- 창고에서 택배를 선택하면 처리 가능한 계약 버튼만 밝아지고, 위험한 계약은 노란 테두리.
- 신뢰도 트랙(v0.3.4 구현)은 마켓 카드·호출 모달·도감 업체 탭 공용.

## 6. 구현 순서

**v0.4 (2026-09-06) 구현됨**: 1~2장·5장 대부분. 남은 것: 마켓 ⚠ 위험 경고 가중치(2장 후단), 창고에서 택배 선택 시 계약 버튼 하이라이트(5장), 난이도 축(4장 → 4단계).


`CUSTOMER_DESIGN.md` 5장의 통합 순서를 따른다. 이 문서 몫은 **2단계**: `canHandle(carrier, parcel)` 하나로 매칭 통합, `caps` 데이터 이전, 통관 상태 머신(대기 턴·지연 이벤트), 냉동 구역·냉동 물류·냉동고 증설, 파손 판정, 원형 3종, 특약 4종, 위험 미리보기. 봇에 원형·특약 구매와 파손 회피 로직 추가.

## 부록. 열어 둔 질문

1. 지연 업체 보상을 호출 시점 기한 기준으로 — 현재 안. 도착 시점 기준이면 규칙이 복잡.
2. 통관 대기 2턴이 표준 3개월 초반에 너무 무거운지. 1개월차는 1턴으로 시작해 월별 +0.5 반올림도 가능.
3. 용달의 ❆ 불가가 냉동 고객이 있는 회사에서 답답한지. 냉동 물류가 시작 계약에 포함되면 괜찮을 것.
