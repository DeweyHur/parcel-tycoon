# 택배 타이쿤 — 출시·BM 계획 v0.1

결정(2026-09-13): **웹 데모 먼저 공개**, BM은 **무료 데모 + 1회 언락**.

## 1. 3단 배포 구조

| 단계 | 채널 | 형태 | 목적 |
|---|---|---|---|
| 1 | itch.io + 웹 아티팩트 | 무료 데모(결제 없음) | 플레이테스트 피드백, 초기 관심·위시리스트 |
| 2 | Google Play | 무료 설치 + 1회 언락 IAP | 모바일 본편 |
| 3 | Steam (+ STOVE 인디) | 데모 + 유료 본편 | PC 관객. 턴제·수치 관리라 본 무대 |

선택 사항: 원스토어·갤럭시 스토어는 Play용 APK 그대로 올리면 되니 나중에 추가. App Store는 Capacitor iOS 타깃 + $99/년이라 2단계 반응을 보고 결정.

**웹에는 결제를 붙이지 않는다.** 웹 결제는 전환율이 낮고 심사·환불 처리가 전부 직접 일이 된다. 웹 데모의 역할은 "본편은 Play/Steam에서" 로 보내는 것.

## 2. 데모 경계

추천: **인수인계 3개월까지** (약 30턴, 40~60분)

- 스토리 비트 23개가 1~3개월에 집중돼 있어 서사적으로 자연스러운 컷이다. 3개월 말 「수습 종료」 시점에 언락 안내.
- 6개월(반기)까지 열면 2시간을 넘겨 Steam 환불 기준과 겹치고, 유료 전환 동기가 사라진다.

데모에서 잠기는 것:
- 4개월차 이후 (달력 후반 이벤트: 추석 폭주, 12월 반송 유예, 인플레이션)
- 시나리오 선택 (성수기·폭염·블프·데일리·12개월 시나리오들)
- 회사 선택(동네 택배 고정), 퍽 슬롯, 준비 마켓, 보험
- 시나리오·회사 선택 화면은 **보여주되 회색 처리**하고 해금 조건 자리에 "본편에서"를 띄운다. 콘텐츠 양이 구매 이유다.

## 2.1 구현 상태 (2026-09-13)

데모 게이트는 레포에 들어갔다 (`feat/demo-gate`).

- `www/js/build.js` — 빌드 플래그 한 곳(`demo` / `demoMonths` / `iap` / `store` 링크)
- `python3 tools/build-web.py --demo` → `dist/parcel-tycoon.demo.html` (대입문만 true 로 바꿔 인라인)
- 3개월 정산 뒤 `Game.closeSummary()` → `_finishDemo()` — 승리도 패배도 아닌 `result.demo`, 「수습 종료」 화면
- 타이틀 「새 런」·시나리오·회사 화면은 보이되 전부 잠김 → 「본편 알아보기」 안내
- 기록 화면에 프로필 내보내기/가져오기(코드 문자열, 합치기 방식)
- 단위 테스트 59개 통과 + 데모/본편 빌드 각각 브라우저로 확인 (데모 3개월차 종료 · 본편 4개월차 진행)

남은 것: `BUILD.store` 링크 채우기, 모바일 IAP 플러그인 연결(`BUILD.iap`), itch.io 페이지 개설.

## 3. 언락 구현

설계 원칙 2(해금은 도전과제로)와 충돌하지 않게, 돈으로 사는 것은 **본편 접근권 하나**뿐이다. 회사·시나리오·퍽 슬롯은 계속 도전과제로만 열린다.

- `profile`에 한 겹 추가: `license = { full: bool, source: 'demo'|'play'|'steam'|'ios' }`
- 빌드 플래그 `cfg.demo`: 월 4 진입 시점(`_startMonth`)과 시나리오·회사·퍽 화면에서 게이트
- 세이브 이어받기: 모바일은 같은 앱이므로 IAP 직후 그대로 이어진다. Steam은 별개 설치라 **프로필 내보내기/가져오기**(JSON → base64 코드 문자열)를 하나 붙인다 — `profile` 구조가 이미 직렬화 가능하니 화면 하나면 된다.
- 데모 세이브는 본편 스키마와 동일하게 유지(버전 필드만 확인)

## 4. 가격

| 채널 | 가격 |
|---|---|
| Google Play 언락 IAP | ₩5,500~7,500 |
| Steam | $7.99 (한국 ₩9,900 전후) |
| App Store 언락 IAP | Play와 동일 티어 |

Steam 30%, Play는 연 100만$ 미만 15%(한국은 2026-12-31부터 결제 5% 분리 구조 적용), itch.io 기본 10%.

## 5. 일정에서 먼저 밟아야 하는 것

1. **Google Play 비공개 테스트 지금 시작** — 개인 계정은 테스터 12명이 14일 연속 옵트인 상태여야 프로덕션이 열린다. 완성 후 시작하면 그것만으로 2주+ 밀린다. 조직 계정은 이 조건이 없지만 D-U-N-S에 4주가 걸려 더 느리다.
2. 웹 데모 공개 → 피드백 수집 (봇 승률로는 잡히지 않는 것: 세션 길이 체감, 3개월 컷의 납득도, 이탈 지점)
3. Steam 스토어 페이지는 출시 최소 2주 전 공개(위시리스트 적립 기간)

## 6. 출시 전 확인 목록

- [ ] **BGM 라이선스** — Suno 칩튠 6곡의 상업적 이용 권한 확인. 무료 플랜 생성물은 상업 이용이 안 된다. 유료 플랜 기간 중 생성분인지, 아니면 교체가 필요한지 먼저 확인할 것 (출시 블로커 가능)
- [ ] 국내 PC 유통 등급분류 — 모바일 스토어는 자체등급분류로 해결되지만 PC는 게임위 등급분류 대상. Steam은 자체등급분류사업자 자격이 확정되지 않은 상태이므로, 국내 PC 판매를 염두에 두면 STOVE를 함께 두는 편이 안전
- [ ] 개인정보처리방침 URL (Play 필수. 수집 없음이어도 문서는 필요)
- [ ] Play 데이터 보안 양식 — 오프라인·수집 없음으로 신고
- [ ] 스토어 자산: 아이콘 512², 피처 그래픽 1024×500, 폰 스크린샷 2~8장, 짧은 설명 80자, 트레일러(Steam)
- [ ] 영어 대사 톤 검수 (IMPLEMENTATION_NOTES "남은 것")
- [ ] 12개월 시나리오 승리 조건 검증, 컷 시나리오 봇 승률 조정
- [ ] 옛 세이브 마이그레이션 없음 → 데모 공개 전 저장 키 버전 정리
- [ ] 사업자등록 (수익 발생 후. Play/Steam 정산 전 세금 정보 등록 필요)

## 7. 하지 않기로 한 것

- **보상형·전면 광고**: 런 중 이득을 주는 보상형은 도전과제 해금과 데일리 시드 기록을 무의미하게 만든다. 월말 정산마다 전면 광고는 정산→마켓→다음 달 계획의 호흡을 끊는다. eCPM도 한국 기준 기대치가 낮다.
- **해금 판매**: 회사·시나리오·퍽 슬롯·마켓 새로고침·파산 후 이어하기 전부 제외.
- **캐주얼 웹 포털(CrazyGames·Poki)**: 광고 수익 배분은 60%/50%로 나쁘지 않지만 한 런 30~120턴은 포털의 3분 세션 패턴과 맞지 않는다. 데모 유통 채널로만 고려.
